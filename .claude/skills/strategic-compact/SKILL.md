# 전략적 컴팩트 스킬

## 문제
자동 컴팩션은 **임의의 시점**에 발동되어 중요한 컨텍스트를 잃을 수 있습니다.
- 구현 도중 발동 → 작업 맥락 손실
- 디버깅 중 발동 → 추적 정보 손실

## 해결책
**논리적 경계**에서 수동으로 컴팩트를 수행합니다.

## 적절한 컴팩트 타이밍

### 좋은 시점 ✅
- 탐색 완료 후, 구현 시작 전
- 계획 확정 후, 코딩 시작 전
- 디버깅 완료 후, 수정 시작 전
- 마일스톤 완료 후, 다음 단계 시작 전
- 대규모 코드 리딩 완료 후

### 나쁜 시점 ❌
- 구현 도중 (관련 컨텍스트 손실)
- 디버깅 도중 (추적 정보 손실)
- 테스트 작성 도중 (테스트 맥락 손실)
- 리팩토링 도중 (변경 추적 손실)

## 컴팩트 전 체크리스트

1. **현재 작업이 논리적 단위로 완료되었는가?**
2. **다음 단계가 새로운 맥락을 필요로 하는가?**
3. **중요한 결정사항이 TodoWrite에 기록되었는가?**

## 컴팩트 요청 방법

Claude Code에서 `/compact` 명령을 사용하거나, 대화 중 "컨텍스트를 정리해줘"라고 요청합니다.

## 핵심 원칙
> "훅이 *언제*를 알려주고, 당신이 *할지 말지*를 결정합니다."

컴팩트는 도구이지 의무가 아닙니다. 현재 맥락이 중요하다면 컴팩트를 미루세요.
