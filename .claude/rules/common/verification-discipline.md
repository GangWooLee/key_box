# 검증 규율 — 증거 없이 완료 선언 금지

## 원칙: Evidence before claims, always

## 5단계 검증 시퀀스

작업 완료를 선언하기 전에 반드시 수행:

1. **명령어 식별** — 주장을 증명할 검증 명령어를 결정
2. **새로 실행** — 캐시나 기억이 아닌, 명령어를 지금 실행
3. **전체 출력 확인** — exit code, 실패 건수, 경고 모두 읽기
4. **일치 확인** — 출력이 주장과 일치하는지 판별. 불일치 시 실제 상태를 보고
5. **증거 첨부** — 증거를 첨부한 후에만 완료 선언

## 즉시 중단해야 하는 위험 신호 (Red Flags)

다음 행동 패턴을 감지하면 스스로 중단하고 검증부터 수행:

| 위험 신호 | 올바른 행동 |
|----------|-----------|
| "아마 될 것입니다" | 명령어 실행으로 확인 |
| "완벽합니다!" (검증 전) | 검증 완료 후 판단 |
| 커밋 준비 (재실행 없이) | `bin/rails test` + `rubocop` 새로 실행 |
| teammate 보고 신뢰 | 독립적으로 테스트 재실행 |

## 적용 시점

| 시점 | 검증 명령 |
|------|----------|
| Phase/Task 완료 시 | `bin/rails test` (최소) |
| PR 전 | `/verify` (전체 6단계) |
| 커밋 전 | `rubocop` + 관련 테스트 |
| 버그 수정 후 | 재현 시나리오 재실행 |

## Phase 시간 추적

Phase 완료 시 실제 소요 시간을 plan 문서에 기록.
예상과 50% 이상 차이 시 나머지 Phase 추정치 재조정.

| 항목 | 규칙 |
|------|------|
| 기록 시점 | Phase 완료 직후 (Quality Gate 통과 후) |
| 기록 위치 | `docs/plans/PLAN_xxx.md` Time Tracking 테이블 |
| 재조정 기준 | Actual ≥ Estimated × 1.5 또는 Actual ≤ Estimated × 0.5 |
| 재조정 행동 | 남은 Phase 추정치를 실적 비율로 보정 |
