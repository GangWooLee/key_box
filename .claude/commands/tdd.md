# TDD 워크플로우 (Test-Driven Development)

엄격한 **RED → GREEN → REFACTOR** 사이클을 따라 구현합니다.

## 프로세스

### 1단계: 인터페이스 설계
- 모델 스키마, 컨트롤러 액션, 서비스 인터페이스를 먼저 정의
- 필요한 마이그레이션 파악

### 2단계: 테스트 먼저 작성 (RED)
- 구현 전에 실패하는 테스트를 작성
- `bin/rails test` 로 실패 확인
- Minitest + fixtures 패턴 사용

### 3단계: 최소 구현 (GREEN)
- 테스트를 통과하는 **최소한의** 코드만 작성
- 과잉 설계 금지

### 4단계: 리팩토링 (REFACTOR)
- 테스트가 통과하는 상태에서 코드 개선
- 중복 제거, 네이밍 개선

### 5단계: 커버리지 확인
- 인증/결제: **100%** 커버리지
- 컨트롤러: **80%** 이상
- 시스템 테스트: **60%** 이상

## 테스트 유형

| 유형 | 도구 | 위치 |
|------|------|------|
| 단위 테스트 | Minitest | `test/models/`, `test/services/` |
| 컨트롤러 테스트 | Minitest | `test/controllers/` |
| 시스템 테스트 | Capybara | `test/system/` |
| 통합 테스트 | Minitest | `test/integration/` |

## TDD 적용 대상
- 새 기능 / 모델 / 서비스
- 버그 수정 (실패 테스트 먼저 → 수정)
- 리팩토링
- 핵심 비즈니스 로직

## 체크리스트
- ✅ 테스트를 먼저 작성했는가
- ✅ 실패를 확인했는가
- ✅ 최소한의 변경만 했는가
- ❌ 구현 후 테스트 작성 금지
- ❌ 테스트 실행 생략 금지
- ❌ 과도한 모킹 금지 (fixtures 우선)

## 관련 워크플로우
- `/verify` — 구현 후 종합 검증
- `/code-review` — 코드 리뷰
