# 실앱 비전 QA — 눈으로 확인하는 마지막 계층

> 2026-07-17 도입. 계기: 폴더 배치 버그(#2)를 소스에서 고치고 단위 테스트까지
> 붙였는데, 실앱에서 같은 증상이 재보고됐다. 원인은 코드가 아니라 **이틀 전에
> 빌드된 바이너리를 계속 dogfood하고 있었던 것**(빌드 Jul 14 < 수정 커밋 Jul 15).
> 테스트 스위트는 소스를 검증하지, 지금 떠 있는 앱을 검증하지 않는다.
> 그 간극은 실제 앱을 띄우고 눈으로 봐야만 닫힌다.

## 언제 하나

- 사용자 눈에 보이는 플로를 고쳤을 때 (배치·집계·reveal/copy·잠금 전이)
- "고쳤다"고 보고하기 전 — 테스트 그린만으로 완료 선언하지 않는다
- 사용자가 "고쳤다는데 안 고쳐졌다"고 하면 **코드보다 바이너리 시각부터 확인**:
  `ls -la build/macos/Build/Products/*/KeyBox.app` vs `git log -1 --format=%ci <수정커밋>`

## 루프

1. **재빌드+재기동** — `scripts/dogfood.sh release`. 빌드→기존 프로세스 종료→재기동을
   한 번에. 이 스크립트를 거치지 않은 실앱 관찰은 증거로 치지 않는다.
2. **잠금 해제는 사용자가** — 마스터 비밀번호는 자동화가 입력하지 않는다(입력 금지
   원칙). 사용자에게 잠금 해제를 요청하고 이어받는다.
3. **테스트 라벨 데이터로 구동** — `vision-e2e-test` 같은 명시적 이름, 더미 값만.
   실 시크릿은 건드리지 않는다.
4. **눈으로 단언** — 스크린샷·줌으로 확인하고 증거를 남긴다.
5. **정리** — 만든 테스트 키/폴더를 UI로 삭제하고, 마지막 스크린샷으로 볼트가
   검수 전 상태와 동일함을 확인한다.

## 체크리스트 (2026-07-17 실측 통과)

| # | 항목 | 확인 방법 |
|---|---|---|
| 1 | 폴더 선택 상태에서 키 추가 → **그 폴더**에 배치 | 폴더 뷰에 행 등장, General 아님 |
| 2 | 사이드바 폴더 카운트 +1 즉시 반영 | 줌 스크린샷 (예: toss 0→1) |
| 3 | 다른 폴더 카운트 불변 | General 3 유지 |
| 4 | 카테고리 카운트 정합 | All Keys/API Keys 동반 +1 |
| 5 | detail 패널 Folders 칩 = 실제 링크 | 칩에 해당 폴더만 표시 |
| 6 | 삭제 → 행 제거 + 카운트 −1 즉시 반영 | 확인 다이얼로그 후 폴더 뷰 empty |

미커버(후속 후보): reveal/copy + 클립보드 30s 소거 링, 잠금/해제 전이, 검색,
폴더 링크 추가/해제 칩, 백업/복구 화면.

## 이 계층이 잡는 것

- **스테일 바이너리** — 테스트가 원리적으로 볼 수 없는 유일한 결함류
- 위젯 테스트가 스텁으로 건너뛴 실제 배선(예: `sheet_modal_test`는
  `selectedFolderIdProvider`를 하드코딩해서 폴더탭→모달 seam을 안 탔다 —
  그 seam은 `test/features/secrets/presentation/screens/dashboard_secret_flow_test.dart`가 커버)
- 렌더링·간격·마스킹 같은 "보여야 아는" 결함
