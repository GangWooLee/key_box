# 제품 요구 문서 (PRD)

> 이것은 1인 제품의 PRD다 — 시장 분석과 페르소나 연극 없이, 실제 사용자(저자)가
> 무엇을 요구했고 무엇을 거부했는지를 기록한다. 이 문서의 효용은 "왜 이 기능이
> 있고 저 기능이 없는가"에 대한 답이 코드 밖에 남는 것이다.

## 문제

개발자의 API 키·토큰·비밀번호는 `.env` 파일, 메모 앱, 클립보드 히스토리,
메신저 DM에 흩어진다. 흩어진 각각은 평문이고, 어디에 뭐가 있는지도 잊힌다.
기존 대안이 안 맞았던 이유는 명확하다:

- **클라우드 볼트(1Password 등)** — 계정, 구독, 그리고 "내 키가 남의 서버에
  있다"는 신뢰 전제. 개인 개발 키 보관에 과하다.
- **OS Keychain** — 임의 시크릿의 정리·검색·메모·백업 UX가 사실상 없다.
- **`.env` + gitignore** — 암호화가 없고, 프로젝트마다 흩어지며, 백업이 곧 유출이다.

KeyBox는 이 셋의 빈틈을 노린다: **로컬에서만 살고, 파일 단위로 암호화되고,
정리·검색이 되는 개인 시크릿 저장소.**

## 사용자와 기준선

사용자는 현재 한 명 — 저자 자신이다. 이것은 부끄러운 사실이 아니라 품질
기준선의 정의다.

- **기준선 A — 저자의 일상 도구**: 자기 실제 시크릿을 넣고 매일 쓸 수 있다.
  암호화 실증, 부팅 안전, 백업/복구 왕복, 실사용 블로커 없음.
  **2026-07-16 도달 판정** — 증거는 [completeness-scorecard.md](completeness-scorecard.md).
- **기준선 B — 남에게 권할 수 있는 배포**: 복구 코드, Developer ID 서명·공증,
  회전 원자성. **미달이며, 격차는 장부로 관리한다** (같은 문서).

## 요구사항

### 반드시 (기준선 A — 전부 구현·실증됨)

1. **볼트** — 마스터 비밀번호 하나로 생성·잠금·해제. 비밀번호는 저장하지 않는다.
2. **시크릿 CRUD** — 이름·값·종류(API 키/토큰/비밀번호/인증서 등)·서비스·환경·
   메모·태그. 값은 항상 암호화 저장.
3. **정리와 탐색** — 폴더(한 시크릿이 여러 폴더에 속할 수 있음), 종류별 필터,
   전문 검색, 사이드바 실시간 집계.
4. **안전한 열람** — 기본 마스킹, 명시적 reveal, 복사 시 30초 자동 소거.
5. **백업/복구** — 단일 파일(.kbx)로 내보내고, 비밀번호만으로 복원한다.
   메타데이터까지 암호화(v3).
6. **비밀번호 변경** — 전체 재암호화 없이(키 계층 덕에) 회전. 회전 전 자동 백업.
7. **자동 잠금** — 유휴 시간 기반, 시간 설정 가능.
8. **감사 로그** — 생성·열람·수정·삭제가 언제 있었는지 기록.

### 하지 않는다 (명시적 비목표)

이 목록은 요구사항만큼 중요하다. 각각은 실제로 거부된 제안이다.

- **2차 비밀번호·작업별 재인증 — 영구 거부.** 사용자 원문: "사용자가 불편하고
  크게 도움이 되지 않는다." 마찰 방어는 사용자를 도구 밖(메모장)으로 밀어내
  순보안을 낮춘다. 보안 강화는 전부 무마찰 방어로만 한다(SECURITY.md 원칙).
- **클라우드 동기화·계정 — 비목표.** 로컬 온리가 이 제품의 존재 이유다.
  네트워크 권한 자체를 선언하지 않는 것으로 강제한다.
- **팀 공유·멀티 사용자 — 비목표.** 개인 도구다.
- **브라우저 확장·자동완성 — 비목표.** 공격 표면 대비 효용이 맞지 않는다.
- **Windows/Linux/모바일 — 당분간 비목표.** macOS 데스크톱에 집중한다.

### 품질 요구 (도메인 특성상 협상 불가)

- 암호화·검증·보안·접근성 코드는 단순화 대상에서 제외한다 — 시크릿 매니저에서
  이 넷은 지워도 되는 코드가 아니다.
- "테스트 그린 ≠ 앱 작동"을 전제로 한다: 암호화는 실기 integration_test로만
  증명하고, 사용자 눈에 보이는 플로는 실앱 비전 QA([qa-vision-e2e.md](qa-vision-e2e.md))로
  재확인한다.
- 완료 선언에는 증거를 첨부한다. 증거 없는 ✓는 스코어카드에 들어갈 수 없다.

## 다음 단계 (기준선 B 백로그, 우선순위순)

1. **복구 코드** — 현재 비밀번호 분실 = 데이터 손실. B의 최대 격차.
2. **Developer ID 서명 + 공증** — 메모리 덤프 방어(get-task-allow 제거)와
   Gatekeeper 신뢰가 이것 하나에 걸려 있다.
3. **회전 원자성** — 현재는 사전 백업으로 완화만.
4. 방어심층 후보(화면잠금 연동 자동잠금, 잠금 시 클립보드 소거, Argon2id 이관,
   부팅 잔해 스윕)는 SECURITY.md 잔여 위험 장부가 관리한다.
