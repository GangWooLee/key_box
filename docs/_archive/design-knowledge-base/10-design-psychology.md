# Phase 10 — 디자인 심리학 & 인지과학

> 사용자의 지각, 인지, 의사결정 프로세스를 과학적으로 이해하고 UI/UX 설계에 적용하는 원칙과 실무 기법

---

## 📌 개요

디자인 심리학은 인지과학, 행동경제학, 지각심리학의 이론을 UI/UX 설계에 직접 적용하는 분야다. 15년 경력의 시니어 디자이너라면 다음을 갖춰야 한다:

1. **과학적 근거**: 추측이 아닌 실증 연구 기반의 설계
2. **정량화된 메트릭**: 로딩 시간(400ms), 버튼 크기(44pt/48dp), 선택지 개수(4±1) 등
3. **실무 마핑**: 이론을 즉시 사용 가능한 디자인 결정으로 변환
4. **혁신의 균형**: 친숙함(Jakob's Law)과 차별화의 줄타기

이 문서는 10개 핵심 법칙 + 추가 원칙으로 구성되며, 각각 디자인 검토 기준(DRC)을 포함한다.

## 🧠 Part 1: 핵심 이론 — 원본 연구 & 정식화

### 1. Fitts's Law (Paul Fitts, 1954)

**원본**: 운동 시간(MT)은 거리(D)와 목표 폭(W)의 함수

**Shannon 정식화** (MacKenzie, 1992):
```
MT = a + b × log₂(D/W + 1)

여기서:
- MT = Movement Time (ms)
- a = y절편 (device별 base latency, 보통 0-50ms)
- b = 회귀 기울기 (device별 속도, 보통 100-150ms)
- D = Distance (픽셀 또는 cm)
- W = Target Width (픽셀 또는 cm)
- ID = log₂(D/W + 1) = Index of Difficulty (bits)
```

**실증 연구**:
- 마우스 클릭: ID=1.0일 때 200-300ms
- 터치 스크린: ID=1.0일 때 250-400ms (마우스보다 20-30% 느림)

**Edge Case — Infinite Width**:
```
화면 모서리 또는 화면 끝에 배치된 버튼은 이론상 W → ∞
따라서 MT = a (기울기 항 제거)

예: macOS Dock 아이콘 (화면 하단)
예: iOS Safe Area 상단/하단 (20pt 이상 여유)
```

**디자인 적용**:
| 대상 | 권장 사이즈 | 근거 |
|------|-----------|------|
| 터치 버튼 | 44pt × 44pt (iOS) | MIT/Apple 연구, 손가락 크기 ~10mm |
| Material 버튼 | 48dp × 48dp | Google Material Design 3, 9-10mm |
| 마우스 클릭 | 32px × 32px 최소 | 마우스 정밀도 높음 |
| 터치 간격 | 8pt 최소 | 오터치 방지 |
| 스티키 스크롤 타겟 | 화면 끝 (W → ∞) | 상단 메뉴바, 알림센터 |

**Steering Law** (Accot & Zhai, 1997):
경로 기반 상호작용 (메뉴 트리, 좌표축 네비게이션)
```
MT = a + b × (C / W)

여기서 C = 경로 길이 (path length)
W = 경로 너비 (corridor width)
```

**실무 체크**:
- ✅ 드롭다운 메뉴: 항목 간 거리 확대 (W 증대)
- ✅ 툴팁: 마우스 1-2cm 이내 배치
- ✅ 슬라이더: 길이 ≥ 100px, 손잡이 ≥ 12pt

### 2. Hick's Law (William Edmund Hick, 1952)

**원본**: 반응시간(RT)은 선택지 개수(n)의 로그 함수

**Hyman (1953) 정식화**:
```
RT = a + b × log₂(n + 1)

여기서:
- RT = Reaction Time (ms)
- n = 선택지 개수
- a = 기본 반응 시간 (보통 100-200ms)
- b = 정보 처리 속도 (보통 70-150ms/bit)
```

**수치 예시** (전형적인 디바이스):
| 선택지 개수 | 계산 | 예상 RT |
|-----------|------|--------|
| 1개 (a, b 보통 값) | a + b×0 | 100-200ms |
| 2개 | a + b×1 | 170-350ms |
| 4개 | a + b×2 | 240-500ms |
| 8개 | a + b×3 | 310-650ms |
| 16개 | a + b×4 | 380-800ms |

**인지적 한계** (설계 목표):
- **0-3개**: 직감적 선택, 고민 최소
- **4-6개**: 적절한 선택, 100-200ms 고민
- **7-12개**: 인지 부하 증가, 500ms 이상 고민
- **13개+**: 의사결정 마비, Choice Paradox 시작

**Progressive Disclosure** 기법:
```
초기: 3개 주요 선택지
→ [더보기] 클릭 시 추가 7개 노출
→ 계층적 검색으로 n 줄임
```

**실증 연구**:
- Schwartz (2004) "The Paradox of Choice": 6개 옵션 > 24개 옵션 (구매율 10배 향상)
- Amazon 1-Click: 선택지 0개, RT = 0ms → 전환율 35% 증대
- Netflix: 초기 5개 추천 카테고리 (이후 스크롤 가능)

**디자인 체크리스트**:
- ✅ 메인 네비게이션: 5-7개 항목 (모바일 4개)
- ✅ 드롭다운 선택지: 최대 9개 (10개 이상은 검색 박스 추가)
- ✅ 라디오 버튼: 최대 5개 (6개+ 시 드롭다운 전환)
- ✅ 설정 탭: 4-6개 (스크롤 최소화)
- ✅ 필터: "인기순/평점순/최신순" 3개 기본, [더 많은 필터] 확장 UI

### 3. Miller's Law (George A. Miller, 1956)

**원본**: 인간이 동시에 처리할 수 있는 정보 단위는 7±2개

**Cowan (2001) 리비전**:
실제 작업 메모리 용량은 **4±1개** (더 정확함)
```
작업메모리 용량 = 4개 청크 (95% 신뢰도)
단기메모리 = 7개 항목 (불안정, 간섭 쉬움)
```

**청크(Chunking) 기법** — 개별 항목 → 의미 있는 그룹:
```
❌ 나쁜 예: 01-234567-890 (11개 숫자)
✅ 좋은 예: 01-2345-6789 (3개 청크)

❌ 나쁜 예: CREDITCARDNUMBER (15개 문자)
✅ 좋은 예: 1234-5678-9012-3456 (4개 그룹)

❌ 나쁜 예: 이메일주소비밀번호이름전화번호주소 (5개 정보)
✅ 좋은 예:
  [계정정보]
  [개인정보]
  [보안설정]
```

**실제 디자인 사례**:
- 전화번호: 3-4-4 패턴 (3개 청크)
- 신용카드: 4-4-4-4 패턴 (4개 청크)
- 우편번호: XXXXX-XXX (2개 청크)
- 시간 표기: HH:MM:SS (3개 청크)

**네비게이션 설계**:
```
❌ 단계별 폼 (5 단계)
  1. 개인정보
  2. 주소
  3. 배송옵션
  4. 결제
  5. 확인

✅ 그룹화된 폼 (3 섹션)
  [1] 배송: 개인정보 + 주소
  [2] 주문: 배송옵션 + 결제
  [3] 확인
```

**정보 밀도**:
- 한 화면에 3-4개 주요 정보만 강조
- 관련 항목끼리 proximity로 청크
- 색상/타이포그래피로 계층 구분

### 4. Jakob's Law (Nielsen, 2000)

**원본**: "사용자는 다른 웹사이트에서 배운 패턴을 당신 제품에도 기대한다"

**인지과학 근거**:
- 멘탈 모델(Mental Model): 사용자가 형성한 "일반적 인터페이스" 예상도
- 전이(Transfer): 학습된 패턴의 새로운 컨텍스트 적용
- 인지적 마찰(Cognitive Friction): 예상과 현실의 불일치가 인지 부하 증가

**Familiarity ↔ Novelty 균형**:
```
혁신 가능 영역 (Innovation Sweet Spot)
    ↑
    |    위험 영역
    |  (사용성 붕괴)
    |  /
  혁신 |/
  성향 |----[최적 영역]----
    |           \
    |            \  위험 영역
    |             \ (평범함)
    +--+--+--+--+--+→
      친숙함 정도
```

**실증 근거**:
- 웹사이트 학습곡선: 처음 사용자가 새로운 패턴 습득 최소 3-5회 반복
- 메타분석: 친숙한 패턴 사용 시 인지 부하 30-40% 감소
- iOS vs Android: 플랫폼 간 전환 사용자의 초기 에러율 50% 증가

**디자인 적용**:
| 요소 | 유지해야 할 패턴 | 혁신 가능 영역 |
|-----|-----------------|-----------------|
| 네비게이션 | 상단/좌측/모바일 하단 | 아이콘 + 라벨 조합, 숨겨진 메뉴 |
| 검색 | 상단 우측 돋보기 | AI 검색, 이미지 검색, 음성 입력 |
| 장바구니 | 우측 상단 아이콘 + 개수 배지 | 플로팅 액션 버튼, 사이드바 |
| 결제 | 안내문 + 진행 표시기 | 1-Click, 소셜 로그인, 생체 인증 |
| 폼 | 왼쪽 라벨, 위에서 아래로 | 라벨 내부, 멀티칼럼, 프로그레시브 |

**성공 사례**:
- Apple: iOS 시스템 패턴 준수 + 미니멀 혁신
- Stripe: 결제 폼의 Familiarity + 1-Click 혁신
- Figma: 데스크톱 설계 도구 패턴 (선택→편집→내보내기)

### 5. 심미적 사용성 효과 (Aesthetic Usability Effect)

**원본**: Kurosu & Kashimura (1995), 심미성 ↑ → 사용성 지각 ↑

**Halo Effect** (심리학):
```
심미성 우수 → 사용자 뇌:
  "이건 좋아 보이니까 사용하기도 쉬울 거야"
  (실제 사용성과 무관한 긍정적 편견)
```

**정량화**:
- 고심미 설계: 사용성 점수 +1.4 포인트 (10점 척도)
- 형용사 연관: 아름다움 ↔ 효율성 r = 0.85 (매우 강함)
- 인내심: 미적 UI에서 오류 발생 시 용인도 3배

**Don Norman "Emotional Design" (2004)** — 3단계:
1. **본능적 레벨** (Visceral): 색상, 형태, 텍스처
   - 대조도, 여백, 타이포그래피
   - 첫 인상: 50ms 이내

2. **행동적 레벨** (Behavioral): 사용 편의성
   - 피드백, 응답 속도, 예측 가능성
   - 작업 완료 시간

3. **반성적 레벨** (Reflective): 브랜드, 자부심, 신뢰
   - 일관성, 정체성, 스토리텔링
   - 장기 만족도

**디자인 체크리스트**:
- ✅ 색상 대비: WCAG AAA (4.5:1 이상)
- ✅ 타이포 계층: 크기, 굵기, 간격 명확
- ✅ 여백: 최소 8pt 배수 시스템
- ✅ 마이크로 인터랙션: 100-300ms 호버 피드백
- ✅ 버튼 상태: 기본 → 호버 → 활성 → 비활성 (4가지)
- ✅ 아이콘 일관성: stroke 1.5pt, 24pt × 24pt 그리드

### 6. Peak-End Rule (Kahneman, 1993)

**원본**: 전체 경험의 기억은 피크 순간 + 끝 순간의 평균에 의존

**수식** (체감 만족도):
```
전체 만족도 ≈ (피크 만족도 + 끝 만족도) / 2

예: 영화 경험
  - 전체 시간: 120분
  - 중간 재미: 3/10
  - 피크(15분): 8/10
  - 엔딩(10분): 9/10
  → 기억된 만족도 ≈ (8 + 9) / 2 = 8.5/10
```

**UI 설계 응용**:
```
❌ 나쁜 경험: 로딩 → 사용 → 저장 실패
  피크: 5/10, 끝: 2/10 → 기억: 3.5/10

✅ 좋은 경험: 빠른 로딩 → 사용 → 성공 애니메이션
  피크: 8/10, 끝: 9/10 → 기억: 8.5/10
```

**구현 기법**:

1. **Success Screens** (완료 화면):
   - 체크마크 애니메이션 (300-500ms)
   - 확인 문구: "완벽합니다!" (감정적 언어)
   - 다음 단계 유도: [계속하기], [공유하기]

2. **Completion Celebrations**:
   - Confetti 애니메이션 (특정 이정표)
   - 음성 효과 (선택): 만족감 +20%
   - 진동 피드백 (모바일): 인지성 +30%

3. **Progress Endpoint 강화**:
   - 마지막 단계: 다른 단계보다 +2-3초 길게
   - 시각적 강조: 크기 ↑ 20%, 색상 포화도 ↑ 30%

**실증 사례**:
- Duolingo: 레슨 완료 → Confetti + "Great job!" → 재사용 의욕 +34%
- Stripe: 계정 설정 완료 → 체크 애니메이션 → 신뢰도 +18%
- Slack: 첫 메시지 전송 → 별 애니메이션 → 재방문 +12%

### 7. Von Restorff 효과 (1933) — 고립 효과

**원본**: 시각적으로 구별되는 항목이 더 잘 기억되고 선택됨

**신경과학**: 주의 포획(Attentional Capture) → 전전두엽 활성화 ↑ 35%

**CTA (Call-To-Action) 설계**:
```
❌ 나쁜 예: 회색 배경에 동일한 회색 버튼들
  버튼 1: [Cancel]
  버튼 2: [Maybe Later]
  버튼 3: [Subscribe]  ← 선택율 12%

✅ 좋은 예: 대조되는 강조
  버튼 1: [Cancel] (회색, 작음)
  버튼 2: [Maybe Later] (회색, 작음)
  버튼 3: [Subscribe] (파랑, 크기 1.5배, 그림자)
  ← 선택율 67% (+455%)
```

**기법**:
| 속성 | 차이 | 영향도 |
|-----|------|-------|
| 색상 | 대조색 (보색) | 매우 강함 (80%) |
| 크기 | 1.5배 이상 | 강함 (60%) |
| 위치 | 격자 중단, 아래쪽 | 중간 (40%) |
| 명도 | 밝기 차이 30% | 강함 (65%) |
| 모양 | 둥근 ↔ 각진 | 약함 (25%) |

**가격 테이블 예**:
```
┌─────────────────┐
│ Standard        │
│ $29/mo          │
└─────────────────┘

┌─────────────────────────┐
│ ★ Recommended           │
│ Pro                     │  ← 별 아이콘, 배경색, 1.2배 크기
│ $79/mo                  │
│ [Try for Free] (파랑)   │
└─────────────────────────┘

┌─────────────────┐
│ Enterprise      │
│ Custom Pricing  │
└─────────────────┘
```

**디자인 체크**:
- ✅ 주요 CTA: 배경 색상 + 주변과 명도 차 30% 이상
- ✅ 보조 CTA: 아웃라인 또는 텍스트 버튼
- ✅ 파괴적 CTA: 빨강 (삭제, 로그아웃)
- ✅ 간격: CTA 주변 24pt+ 여백

### 8. 연속 위치 효과 (Serial Position Effect, Ebbinghaus 1885)

**원본**: 나열된 항목 중 처음과 마지막이 기억되기 쉬움

**수식** (기억율):
```
기억율 = Primacy Effect + Recency Effect

Primacy (처음 3-4개 항목): 기억율 +40%
Recency (마지막 2-3개 항목): 기억율 +30%
Middle: 기억율 기준선
```

**네비게이션 설계**:

```
상단 메뉴 바 (좌→우):
[홈] [서비스] [커뮤니티] [마이페이지] [고객지원]
 ↑                                      ↑
 Primacy (집중)                   Recency (퇴출)
 중요도 1순위                      중요도 3순위
```

**사이드바 네비게이션** (위→아래):
```
선호도 순서:
1순위: 상단 3-4개 (Primacy) → [홈, 인기, 추천, ...]
2순위: 하단 2-3개 (Recency) → [..., 설정, 로그아웃]
3순위: 중간 항목 → [덜 중요한 메뉴]
```

**리스트 아이템 순서**:
```
❌ 알파벳순: 사용자 스캔 시간 ↑ 40%
✅ 중요도순:
  1. (상단) 가장 인기/자주 사용
  2. (중간) 보조 기능
  3. (하단) 드물게 사용

선택율 예시:
  상단: 45% | 중간: 30% | 하단: 15% | 스크롤 숨김: 10%
```

**디자인 체크리스트**:
- ✅ 네비게이션 순서: 빈도 또는 중요도 기반
- ✅ 탭 순서: [활성 탭] [자주 사용] [...] [설정]
- ✅ 드롭다운: 최근 사용 ↑, 알파벳 ↓
- ✅ 모바일 탭바: 5개 이하, 중간에 FAB (Floating Action Button)

### 9. Zeigarnik 효과 (1927) — 미완성 과제 효과

**원본**: 완료되지 않은 작업이 완료된 작업보다 더 잘 기억됨

**심리학**: 인지적 긴장(Cognitive Tension) → 해소하려는 동기 ↑

**공식화**:
```
재방문 의욕 = (진행도) × (남은 거리의 불확실성)

예:
  0% 진행 → 재방문 의욕 낮음 (이미 포기)
  30% 진행 → 재방문 의욕 중간
  70% 진행 → 재방문 의욕 매우 높음 (거의 다 왔는데!)
  100% 진행 → 의욕 상실 (다음 작업으로)
```

**Endowed Progress** (Nunes & Drèze, 2006):
Loyalty 카드에 처음부터 일부를 채운 후 시작
```
❌ 10 칸 중 0개 완료: 시작 의욕 20%
✅ 10 칸 중 2개 완료 (선착 보너스): 시작 의욕 +34%
```

**UI 적용**:

1. **Progress Bars** (진행 표시):
   ```
   ■■■■□□□□□□ 40%

   시각적 강조:
   - 색상 + 수치 결합 (중복 인코딩)
   - 현재 단계 / 전체 단계 (예: Step 3 of 5)
   - 남은 시간 (예: ~2분 남음) ← 동기 유지 중요
   ```

2. **Habit Stacking**:
   ```
   체크리스트 UI:
   ✓ 프로필 작성 (완료)
   ✓ 첫 프로젝트 생성 (완료)
   ○ 팀 멤버 초대 (진행 중 - 강조)
   ○ 설정 커스터마이징 (미시작)
   ○ 통합 설정 (미시작)
   ```

3. **Streaks & Badges** (연속성):
   - "🔥 7일 연속" 표시
   - 뱃지: "일주일 도전 완료"
   - 다음 단계: "14일까지 3일 남음"

**실증 데이터**:
- Duolingo: 연속 학습 스트리크 → 재방문율 +67%
- Fitbit: 활동 진행바 → 목표 달성율 +42%
- GitHub: 커밋 히트맵 → 기여도 일관성 +55%

### 10. 추가 원칙들

#### 10.1 Doherty Threshold (Walter J. Doherty & Ahmet A. Thadani, 1982)

```
응답 시간 ≤ 400ms → 상호작용 연속성 지각
응답 시간 > 400ms → 사용자가 "기다리고 있음" 인식 시작
```

**구현**:
- 버튼 클릭 → 즉시 피드백 (색상 변화, 스케일): 50-100ms
- API 호출 → 200-300ms 내 응답
- 페이지 로드 → 첫 콘텐츠: 1초 이내

**로딩 스트래티지**:
```
❌ 400ms+ 단순 로딩 스피너: 포기율 50%
✅ 200ms 스키 스크린 + 300ms 콘텐츠: 포기율 8%
✅ 150ms 응답 + Optimistic UI (미리 업데이트): 가장 좋음
```

---

#### 10.2 Goal-Gradient Hypothesis (Hull, 1934)

```
목표까지의 거리 ↓ → 노력 강도 ↑

예: 마라톤 선수
  40km 지점: "아직 2km, 힘내자!" (속도 ↑ 15%)
  39km 지점: "이제 거의 다 왔다!" (속도 ↑ 25%)
```

**UI 설계**:
```
회원가입 단계:
[1/5] [2/5] [3/5] [4/5] [5/5]

마지막 2단계에서:
- 진행바 색상 변화 (회색 → 초록)
- 폰트 크기 +10%
- "거의 다 왔어요! 🎉" 메시지
```

---

#### 10.3 Mere Exposure Effect (Zajonc, 1968)

```
반복 노출 → 호감도 ↑

공식:
호감도 = Base + k × ln(Exposure Count)

여기서 k = 친숙도 증가율 (보통 0.05-0.15)
```

**응용**:
- 온보딩: 처음 3-5일 집중 노출 → 7일차 이후 습관화
- 새 기능: 일주일 3회 미니 팁 → 학습곡선 완만
- 브랜드: 일관된 로고, 컬러 → 신뢰도 상승

---

#### 10.4 Loss Aversion (Kahneman & Tversky, 1979)

```
손실의 고통 = 이득의 기쁨 × 2 (약 2배)

예: $100 번다 vs $100 잃는다
  → 이득 심리: 약간 기쁨
  → 손실 심리: 매우 큰 슬픔 (약 2배)
```

**UI에서의 위험 신호**:
- 삭제 확인: "작업 삭제됨 (5분 내 실행 취소)"
- 결제 변경: "새 요금제로 변경하시겠습니까?"
- 계정 탈퇴: "계정을 삭제하면 모든 데이터가 영구 삭제됩니다"

**디자인 기법**:
| 상황 | 손실 최소화 전략 |
|-----|------------------|
| 가격 인상 | "새 기능이 포함되어 +$10 투자" (손실 ↓ 약 30%) |
| 데이터 삭제 | 휴지통 유지 (30일), 실행 취소 옵션 |
| 기능 제거 | 사전 공지 (30일), 마이그레이션 가이드 |

---

#### 10.5 Anchoring Bias (Tversky & Kahneman, 1974)

```
첫 번째 수치 → 이후 판단의 기준점 역할

예: 가격 책정
  ❌ "$50" → [할인가: $30]
  ✅ "$100" (높은 고정가) → [할인가: $30] (기준: 70% 할인!)
```

**UI 응용**:
- 가격 테이블: 표준($79) 다음에 프로(프리미엄): 실제로는 $79 → 프로 선택율 ↑ 40%
- 스토리지 플랜: 1GB (무료) → 100GB (프리미엄): 100배 차이 → 프리미엄 = 합리적 가치관

---

#### 10.6 Social Proof (Cialdini, 1984)

```
구매율 ∝ (긍정 리뷰 수) × (별점 평균)

리뷰 0개: 전환율 2%
리뷰 5개: 전환율 8%
리뷰 50개: 전환율 15%
리뷰 500개: 전환율 18% (포화)
```

**UI 패턴**:
| 패턴 | 예시 | 전환율 향상 |
|-----|------|-----------|
| 별점 + 리뷰 | ★★★★★ 4.8/5.0 (2,841 reviews) | +25% |
| 라이브 활동 | "지금 123명이 보는 중" | +18% |
| 유명인 추천 | "Apple, Google이 신뢰합니다" | +22% |
| 사용자 통계 | "50만 명이 사용 중" | +15% |
| 최근 구매 알림 | "3시간 전 누군가 구매했습니다" | +12% |

## 🎯 Part 2: 실무 적용 — 디자인 의사결정 맵

### Fitts's Law → 버튼 배치 및 크기

```
상황 분석:
1. 사용 빈도: 높음 → W ↑ (더 크게)
2. 사용 정확도: 중요 → W ↑ (더 크게)
3. 문맥: 모바일 vs 데스크톱

의사결정:
┌─────────────────────────────────────┐
│ 주요 CTA (고빈도, 중요)            │
│ 48dp × 48dp (터치)                  │
│ 또는 화면 끝 배치 (무한 폭)        │
├─────────────────────────────────────┤
│ 보조 CTA (중빈도)                   │
│ 32-40dp (터치) / 24-32px (마우스)  │
├─────────────────────────────────────┤
│ 텍스트 링크 (낮은 중요도)           │
│ 최소 32dp (터치), 호버 상태 명확    │
└─────────────────────────────────────┘
```

### Hick's Law → 선택지 개수 최적화

```
Step 1: 현재 선택지 개수 계산
  예: 필터 버튼 = [가격순, 평점순, 최신순, 인기순,
                    할인순, 거리순, 배송비순, 리뷰순] = 8개

Step 2: RT 계산 (일반적 b=100ms 가정)
  RT = 200 + 100 × log₂(8 + 1)
     = 200 + 100 × 3.17
     = 517ms (반응시간)

Step 3: 최적화 의사결정
  517ms > 400ms (Doherty) → 너무 느림
  → 기본 4개 + [더 보기] 버튼으로 분리
     RT = 200 + 100 × log₂(5) = 432ms (여전히 길음)
  → 기본 3개 + [필터] 이모달로 변경
     RT = 200 + 100 × log₂(4) = 400ms (최적!)
```

### Miller's Law → 정보 그룹화

```
체크아웃 폼 재설계:

❌ 기존 (청크 분석):
  [이름] [성] [이메일] [전화] [주소1] [주소2]
  [도시] [주/도] [우편번호] [나라] [신용카드] [CVC]
  → 12개 청크 (Miller's Law 위반, RT ↑)

✅ 개선 (그룹화):
  ┌─ [배송정보]
  │  [이름] [성] [이메일] [전화]
  │  [주소]
  │  [도시] [주/도] [우편번호]
  ├─ [결제정보]
  │  [카드번호] [만료일] [CVC]
  └─ [배송방법]
     [표준 배송] [빠른 배송] [특급]
  → 4-5개 청크 (최적)
```

## 📋 Part 3: 디자인 리뷰 체크리스트 (Design Review Checklist)

### Cognitive Principles DRC (Design Review Checklist)

```
평가 기준: ✅ 만족 | ⚠️ 부분적 | ❌ 미충족

┌─ Fitts's Law ──────────────────────────────┐
│ ✅ 주요 CTA ≥ 44pt × 44pt (모바일)         │
│ ✅ 마우스 타겟 ≥ 32px 또는 화면 끝 배치    │
│ ✅ 타겟 간 간격 ≥ 8pt (오터치 방지)        │
│ ✅ 경로 기반 UI (메뉴): 경로 너비 ≥ 20pt   │
└────────────────────────────────────────────┘

┌─ Hick's Law 및 Progressive Disclosure ────┐
│ ✅ 기본 선택지 ≤ 5개 (최적 4개)            │
│ ✅ 6-9개 선택지: 검색 박스 포함             │
│ ✅ 10개+: 그룹화 또는 [더 보기] UI          │
│ ✅ 드롭다운 최대 9개 (초과시 검색 추가)    │
└────────────────────────────────────────────┘

┌─ Miller's Law (Chunking) ──────────────────┐
│ ✅ 폼 필드: 한 화면에 4-6개 (최대 7)       │
│ ✅ 네비게이션: 3-5개 주요 항목              │
│ ✅ 리스트 그룹: 관련 항목끼리 proximity     │
│ ✅ 시각적 계층: 색상/타이포 3-4단계        │
└────────────────────────────────────────────┘

┌─ Jakob's Law (Mental Models) ──────────────┐
│ ✅ 표준 패턴 준수: 네비게이션, 검색, CTA   │
│ ✅ 혁신 영역 명확: 설명 텍스트 추가 +20%    │
│ ✅ 온보딩: 새 패턴 학습 가이드 포함         │
│ ✅ 일관성: 동일 기능 = 동일 UI/UX          │
└────────────────────────────────────────────┘

┌─ Aesthetic Usability Effect ───────────────┐
│ ✅ 색상 대비: WCAG AAA (≥ 4.5:1)           │
│ ✅ 타이포그래피: 명확한 계층 (4단계 이상)  │
│ ✅ 여백 시스템: 8pt 배수 (8, 16, 24, 32)   │
│ ✅ 호버 상태: 모든 상호작용 요소            │
│ ✅ 아이콘 일관성: 스타일, 굵기, 크기       │
└────────────────────────────────────────────┘

┌─ Peak-End Rule ────────────────────────────┐
│ ✅ 성공 화면: 체크마크 애니메이션 (300ms)   │
│ ✅ 완료 피드백: "완벽합니다!" (감정적)      │
│ ✅ 다음 단계: 명확한 CTA 포함               │
│ ✅ 오류 처리: 긍정적 톤, 해결책 제시        │
└────────────────────────────────────────────┘

┌─ Von Restorff Effect (Isolation) ──────────┐
│ ✅ 주요 CTA: 색상 + 크기 + 위치 모두 강조   │
│ ✅ 보조 CTA: 아웃라인 또는 텍스트           │
│ ✅ 가격 테이블: 권장 옵션 시각적 강조       │
│ ✅ 위험 액션: 빨강, 확인 대화상자           │
└────────────────────────────────────────────┘

┌─ Serial Position Effect ───────────────────┐
│ ✅ 네비게이션 순서: 빈도 또는 중요도 순    │
│ ✅ 상단 3-4개: 주요 기능                    │
│ ✅ 하단 2-3개: 설정/퇴출 기능               │
│ ✅ 탭 순서: [활성] [자주] [...] [설정]     │
└────────────────────────────────────────────┘

┌─ Zeigarnik Effect (Progress) ──────────────┐
│ ✅ 진행바: 수치 + 색상 모두 표시            │
│ ✅ 체크리스트: 완료/진행/미시작 명확 구분   │
│ ✅ 남은 시간: "~2분 남음" 동기 유지         │
│ ✅ 연속성 시각화: 스트리크, 뱃지            │
└────────────────────────────────────────────┘

┌─ Doherty Threshold (400ms) ────────────────┐
│ ✅ 버튼 응답: ≤ 100ms (즉시 피드백)        │
│ ✅ API 응답: ≤ 300ms (스켈레톤 포함)       │
│ ✅ 페이지 로드: ≤ 1000ms (First Paint)     │
│ ✅ 로딩 UI: 스피너 또는 스켈레톤 스크린     │
└────────────────────────────────────────────┘

┌─ Social Proof & FOMO ──────────────────────┐
│ ✅ 별점 표시: 리뷰 개수 + 평균 포함         │
│ ✅ 라이브 활동: "지금 N명이 보는 중"        │
│ ✅ 한정성: "재고 3개 남음" (정직한 표시)    │
│ ✅ 사용자 통계: 신뢰도 있는 수치            │
└────────────────────────────────────────────┘
```

## 🎨 Part 4: Vibe Coding Guide — 심리학 기반 미시 상호작용

### 상태 별 마이크로인터랙션 스펙

```
1. 버튼 기본 상태 (Idle)
   - 배경색: 브랜드 색상
   - 텍스트색: 흰색 (대비 4.5:1+)
   - 그림자: 0px (flat) 또는 2px (깊이)
   - 상태: 정적

2. 호버 상태 (Hover) — 100-150ms 트랜지션
   - 배경색: 밝기 +10% (또는 채도 +15%)
   - 그림자: 2px → 8px (깊이감 ↑ 400%)
   - 스케일: 1.0 → 1.05 (미묘하지만 감지 가능)
   - 커서: pointer (손가락 모양)

3. 활성 상태 (Active/Pressed) — 50ms 즉시 응답
   - 배경색: 밝기 -15% (눌린 느낌)
   - 그림자: 0px (눌린 상태)
   - 스케일: 1.0 → 0.97 (압축)
   - 피드백: 경미한 진동 (모바일)

4. 비활성 상태 (Disabled)
   - 배경색: 회색 (채도 -60%)
   - 불투명도: 50%
   - 커서: not-allowed
   - 텍스트: 회색
```

### 성공/오류 상태 애니메이션

```
성공 (Success) — 총 1.2초
├─ 0-300ms: 체크마크 그리기 애니메이션
│  path { stroke-dashoffset: 0; }
│  (SVG stroke-dasharray 사용)
├─ 300-600ms: 배경 색상 변화 (회색 → 초록)
│  background: linear-gradient(to right, ...)
├─ 600-900ms: 스케일 업 (1.0 → 1.05) + 회전
│  transform: scale(1.05) rotate(5deg);
└─ 900-1200ms: 안정화, 다음 CTA 강조 (fade-in)

오류 (Error) — 총 800ms
├─ 0-100ms: 입력 필드 배경 회색으로 깜빡임 (주의 포획)
│  background: #fff3cd;
├─ 100-300ms: 좌우 흔들기 (shake)
│  animation: shake 0.2s 2 times;
├─ 300-500ms: 빨강 테두리 강조 (border: 2px solid #dc3545;)
├─ 500-700ms: 오류 메시지 페이드인 (opacity: 0 → 1)
│  color: #dc3545; font-size: 12px;
└─ 700-800ms: 포커스 (입력 필드로 커서)
```

### 로딩 상태 전략

```
시간대 별 UI 전략:

0-100ms: 아무것도 안 함 (너무 빨리 로딩될 수 있음)

100-300ms:
  - Optimistic UI (낙관적 미리 업데이트)
  - 예: 버튼 클릭 → 즉시 UI 변경 (실제 응답 전)
  - 실패시 롤백

300-1000ms:
  - 스켈레톤 스크린 (Skeleton Screen)
  - 예: [박스] [박스] [박스] (실제 레이아웃 미리 보기)
  - 로딩 스피너 최소화

1000ms+:
  - 명시적 로딩 표시
  - 진행 바 + 남은 시간 ("약 5초 남음")
  - 배경 작업 표시

취소 옵션:
  - 3초+ 진행시 [취소] 버튼 활성화
  - "작업이 오래 걸리고 있습니다. 취소하시겠습니까?"
```
